💎

수로 보석금 ↔ 보석금 관리 자동 연동

신청 처리 → 보석금 내역 자동 등록 + 기존 누락 일괄 채움

❌ 현재 문제
수로 보석금 신청
멤버가 신청 → 관리자 "입금 확인" or "노블 해제" 클릭
→ bail_requests 상태만 바뀜
보석금 관리 화면
관리자가 별도 화면에서 "납부자/수령자/수량" 손으로 입력해야 보임
→ bail_history 따로 입력 안 하면 누락
✅ 해결 방안
1
스키마: bail_history에 bail_request_id 컬럼 추가
신청-내역 1:1 연결 → 중복 방지 + 되돌리기 시 자동 삭제
2
자동 sync 훅 4곳 추가
  • _bailApprove (입금 확인 단건)
  • _bailUnlock (노블 해제 단건)
  • _bailBulkProcess('noble_unlocked') (일괄)
  • _bailBulkImportSave (엑셀 임포트)
3
되돌리기·삭제 시 자동 정리
_bailRevert·_bailDelete 시 연결된 bail_history 자동 삭제
4
백필: 기존 누락 일괄 채움 버튼
approved/noble_unlocked인데 bail_history 없는 row → 한번에 채움
🔗 필드 매핑
bail_history (보석금 관리) ← bail_requests (수로 신청)
date←processed_at의 날짜 (없으면 오늘)
payer←payer_char
receiver←processed_by (처리한 관리자)
amount←total_amount
memo←"[수로] {half_year} {offense_count}회차 ×{multiplier}"
bail_request_id 🆕←id (신청 row의 PK)
📋 Supabase에서 실행할 SQL (1줄)
ALTER TABLE bail_history ADD COLUMN IF NOT EXISTS bail_request_id BIGINT REFERENCES bail_requests(id) ON DELETE SET NULL;
CREATE INDEX IF NOT EXISTS idx_bail_history_request_id ON bail_history(bail_request_id);
🔘 백필 버튼 (보석금 관리 화면 상단에 추가)

처리된 신청 중 보석금 내역에 누락된 것만 일괄 추가

⚡ 진행 순서
  1. 위 SQL 1줄 Supabase에서 실행
  2. 코드 패치 → git push (자동 배포)
  3. 보석금 관리 화면 → "🔄 누락분 동기화" 버튼 1회 클릭 (기존 누락분 한 방에 채움)
  4. 이후 신청 → 처리 시 자동 등록 (별도 작업 불필요)
